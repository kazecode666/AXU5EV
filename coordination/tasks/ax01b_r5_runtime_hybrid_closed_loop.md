# AX-01B — R5命令/轨迹集成与生成C＋FOC RTL电机闭环

> 交给本地Codex连续实施A—F，正常检查点无需逐项询问，最后一个实现PR统一Review。任务是实际接通闭环，不再交付一轮只有资料、接口声明或录制输入回放的成果。

**Goal：** 在PR5的软件组件和PR53 p3电流核基础上，补齐原Host_Core命令/轨迹及必要运行管理，让生成C与实际FOC RTL通过实时反馈共同控制原Simulink电机/逆变器，并保留同次Run继续下发点位的操作。

**Architecture：** R5软件模型包含命令处理、S曲线、位置P、速度PI、Reference_Manager与原五态对齐；本轮先在PC执行其生成C。PL侧复用p3原SV，加最小帧锁存/结果提交适配，通过Vivado/XSI参与闭环。交换接口本轮是可运行的仿真实现，不冒称已实现AXI总线或R5实时任务。

**Tech Stack：** 本机已有MATLAB/Simulink/Stateflow、ERT及MinGW；HDL Verifier＋Vivado Simulator/XSI。不升级/重装工具，不以解决Simulink托管SIL环境问题为本轮前置任务。

**Spec与来源：** 已合并PR5、`integration/ps_pl/INTERFACE.md`、现有主模型及`pmlsm_point_move_step.m`/`pmlsm_scurve_profile.m`、`references/legacy/FOC_HDL_TIMING_CONTRACT.md`、原MIL/DSP接口资料。本任务中的新模型、桥接和运行入口均为拟实现项，不是现有功能。

## 范围与选择

选择“先接通完整软件/RTL仿真”，而不是继续逐个外环回放，或现在同时建设整套Vitis/AXI/驱动板工程。前者已经由PR5完成，后者会把控制集成与真实硬件问题混在一起。板卡固定AXU5EVB-E，单Cortex-R5F方向；R5上板、真实AXI、5EV重综合/布线和实际ADC/位置接口归下一轮。

本轮终点：运行同一共享电机环境，用户通过面板提交目标；轨迹及外环确实来自生成C，电流计算确实来自p3 SV，电机实际反馈再次进入这两部分。不得用固定CSV驱动RTL代替闭环，不把GM模型当成RTL。

## Review重点（落实在正常场景中，不另设测试流程）

1. 同次Run发送新目标是否真正进入生成C，面板不再在PC额外产生另一条轨迹。
2. C是否每100µs只调用一次step，命令、位置/速度反馈、对齐状态的先后关系是否沿用原模型。
3. p3九路输入是否整帧稳定，314拍结果相位是否被外围改变，PI/AW末拍状态是否正常更新。
4. 50µs应用边界是否只存在一次；PWM关闭后机械继续演化，不能把duty=0当成已实现门极禁止。
5. R5软件、固定FOC和RTL使用的舍入/饱和、角度符号及输入帧是否一致；不拿M2浮点/定点死区例外放行新的接口错误。

## A — 将原Host_Core接入R5运行模型

**Consumes：** 原主模型的Simple_Host/Host_Core、点位函数与PR5组件。
**Produces：** `AXU5EV_R5_Runtime.slx`，命令/反馈输入，电流参考/偏置/运行状态输出。

- [ ] 在已有模型中确认Host_Core、轨迹、调度、对齐及Reference_Manager的实际执行顺序，直接据此提取；短表写进接口文档即可，不另开长篇审计。
- [ ] 将目标草稿、发送开关、模式/使能与复位作为运行输入；将`pmlsm_point_move_step`及S曲线状态放入软件模型。显示、SDI、负载和电机对象留仿真侧，不生成到R5。保留原AutoStart可选默认，不擅自改变初始化默认10mm/5s/V10/A100。
- [ ] 保持“修改目标草稿不执行、发送一次接收一次、Ready后再接下一目标、Busy拒绝不排队、重复目标确认不重启”。不加入运动中改目标重规划。
- [ ] 用离散软件时基替代依赖仿真墙钟的输入；初始化一次、后续100µs持续调用。暂停/继续不清控制状态。轨迹与原参考在实际控制采样点对应；不能用新的整帧延迟修补调用顺序。
- [ ] 复用已有PWM/PI_Reset/Init_Reset及原故障/手动清除逻辑，保持请求与实际许可分开。正常PWM关断不会重置电机位置；故障消失/清除不自行恢复运动。原点位中断状态若需要显式恢复，按已有模型处理，不擅自新增自动续跑或新的状态机。
- [ ] 在一次正常模型运行里确认连续目标和原五态仍可执行；下一阶段直接复用这个运行模型，不再只停留于组件回放。

## B — 让生成C在线执行，而不是读取预录输入

**Consumes：** A的软件运行模型。
**Produces：** 该模型生成C及在Simulink中在线调用它的组件。

- [ ] 沿用PR5的ERT/MinGW生成路径，扩展生成完整Runtime；参数来自原外部初始化。命令和目标必须是运行输入，而不是编译时固定数组。
- [ ] 首选以离散C MEX S-function薄包装接入生成代码；已有可用C Function封装也可使用。只写输入装载、调用`initialize/step/terminate`和输出读回；明确100µs触发及状态归属。不能在1µs对象步或一次求解器多次求值时重复推进软件状态，不能因包装无意中延迟一个控制采样。
- [ ] 主机模型与其生成C在相同输入下比较相关参考/轨迹/对齐输出，沿用PR5的1e-12软件数值比较尺度；状态/命令接收事件应一致。检查本轮新增内容即可，不重复全部历史PR5组件用例。
- [ ] 不为Simulink托管SIL失败单独展开工具环境修复。采用自定义C集成时，明确称“生成C主机闭环”，不是托管SIL通过或R5实机通过。原生成文件不能为迁就包装而手改。

## C — 实现数据转换和最小帧适配

**Consumes：** 软件参考/偏置/模式与电机同拍反馈、已接受p3 SV。
**Produces：** 模型/RTL共用的数值边界、帧保持和应用事件。

- [ ] 软件输出的dq参考、偏置、对齐模式、PI复位组成一次提交；三相电流/位置等反馈使用一次采样快照。用字段明确的结构/Bus和一个提交事件实现即可，不提前建AXI事务、DMA、TCP或通用消息系统。
- [ ] 沿用`pmlsm_foc_fixed_config`的位宽、Convergent舍入及Saturate。电流signed32/24、角度signed40/32、电角速度signed40/24、母线unsigned32/24、duty unsigned32/30。40位不能截成int32；输出占空比按小数位还原，不再套旧counts/Gain/Bias或相反极性。
- [ ] 实时角度/对齐固定角/偏置路径沿用原选择公式，真实电角度与控制电角度分开；本轮使用模型提供的位置反馈，不冒称已经实现光栅接收或ADC。需要的新PL角度路径先在集成模型中显式实现并记录其尚未硬件化。
- [ ] p3先保留50MHz/5000拍配置用于功能联合仿真。九路输入在本帧首有效边沿前建立并保持到末拍，不因314拍算出结果就修改输入或停时钟；`ce_out`不是帧结果有效。整体复位、时序控制复位和数据端PI_Reset分别处理。
- [ ] 外围模块锁存三相结果并保持可读取的帧状态；在采样后50µs统一应用。裸核314拍只是参考，新增寄存器后的实际捕获边沿必须按电路确定。原环境中的PWM半周期等待与新适配只能选一个负责生效，不能叠成“计算时间＋50µs”或两次50µs。
- [ ] 明确本轮仿真事件顺序：控制采样→软件调用及整体提交→p3输入建立/计算→应用。初版软件计算与寄存器交换按零执行耗时的功能模型处理，保留因果顺序；这不是R5/AXI零耗时的硬件结论。未来实测时延另行加入，不偷偷延后一帧后仍称原算法等价。

## D — 接通三种后端的同一电机环境

**Consumes：** A—C；原电机、平均逆变器和Host面板。
**Produces：** `AXU5EV_Hybrid_ClosedLoop.slx`可运行的在线反馈闭环。

- [ ] 停止仿真后可选择`model_fixed`（完整R5模型＋定点FOC）、`c_fixed`（完整生成C＋定点FOC）、`c_rtl`（同一生成C＋实际p3 RTL）。三者共用对象、参数、量化边界和应用时刻；原纯浮点模型留作外部控制性能参考，不重复放进一条反馈链。
- [ ] `c_rtl`用Vivado/XSI实际运行p3。优先借用已有Step7C/本地M4的连接经验；必要的旧来源为`FPGA_XC7A200T_Study/scripts/step7c_generate_foc_cosim.m`，只参考运行库构建/时基/端口配置。不能复制旧手写FOC、旧counts接口、私有API修补或整个历史工程当新实现。
- [ ] Simulink对象继续1µs，HDL内部20ns；明确交换时间比例、首次复位与首有效帧。输出保持到可采样，不用1µs端口读取20ns单拍脉冲；发现量化交换步引入附加延时，应在两种对照路径统一事件，而非任意平移曲线。
- [ ] 面板在运行中编辑/发送目标，软件C计算轨迹/参考，RTL duty驱动逆变器，电机反馈进入下一帧；原Simulink外环、轨迹不得在旁边重复控制。
- [ ] 已有PWM禁止及故障禁止作用于实际输出许可，不冻结电机、不强行清零速度/位置。母线仍用当前基准输入，默认死区保留一次，不增加补偿。

## E — 三组正常功能场景收敛

不新增冒烟、故意破坏输入、哈希验证或全历史回归；以下就是本轮新增闭环功能本身的运行验证。

| 场景 | 要证明的实际行为 |
|---|---|
| 正常点位＋连续目标 | 至少一次原标准1mm/1.2s场景；另在同一次Run中到位后发送至少两个新目标，包含一次反向。经过面板绑定入口而不是直接写下游x_ref；记录接受目标/Ready/实际位置。原0.02mm到位窗和5次位置事件不改 |
| 手动对齐后运动 | 开启原对齐、手动Start、完整10000/30000/2000计数，完成后继续发点位。保留原机械反馈与偏置计算，不能只固定位置输入再称物理对齐通过 |
| 正常启停与原复位/故障 | 运行中PWM关断后机械继续；PI复位不等于Init复位或清故障；使用现有故障及人工恢复路径验证不自动重启，不新增故障注入框架 |

- [ ] 先在`model_fixed/c_fixed`定位本轮软件集成差异，随后在`c_rtl`完成实际闭环；这些是同一任务内部推进，不拆多个等待批准的交付。最终必须有c_rtl真实点位和连续目标证据。
- [ ] 命令、对齐状态及应用时刻先对齐，再比较x/v/id/iq、参考和实际duty。相同量化输入与状态下，p3结果应逐位一致；生成C微小数值差不能变成错误的提交帧。每组给出简短最大/RMS差和关键事件，不为追曲线重调PI、改死区或放宽到位窗。
- [ ] 重点比较`c_fixed`与`c_rtl`：同一生成C、同一数据转换和应用事件，定点FOC只是RTL功能参考；若不同先查帧、类型、角度和初始化。M2的浮点/定点死区例外不能套用为RTL接口错误的豁免。
- [ ] 长对齐或其他场景若受实际环境限制未能完成，保留已完成的闭环并明确该项未完成；不能拿短回放替代或写整轮完成。运行日志精简提交，完整波形保留本地。
